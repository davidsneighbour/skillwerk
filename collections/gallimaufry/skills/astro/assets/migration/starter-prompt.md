# Astro migration starter prompt

Adapt this prompt to the repository. Replace the scope and source placeholders with known facts, or state that they are unknown. Providing a reusable prompt does not authorise file edits.

```text
Migrate [agreed scope] to Astro, preserving the accepted source site's public design, behaviour, content, metadata, URLs, media, downloads, forms, redirects, and deployment requirements.

Inspect repository instructions, worktree changes, source and build configuration, existing tracking, and available source artifacts first. Follow the existing branch, task, and approval policies. Identify the accepted parity source with evidence; ask a focused question if competing sources would change the outcome.

Select a compatible target Astro version and rendering model. Reuse existing plans and create only the missing documentation needed for the task. Do not rewrite agent instructions, require new tracking tools, create issues or milestones, or impose a branch without authorisation.

Migrate a representative route before expanding to coherent route and system groups. Keep source material recoverable. Compare generated output and rendered behaviour against the accepted source, record evidence, and distinguish implementation from verified parity. Keep improvements separate and record authorised differences explicitly.

Use one agent for small work. If delegation is available and authorised, assign independent groups only after shared architecture and file ownership are clear. Keep integration and final verification with the lead agent.

Report migrated scope, checks, accepted differences, untested services, and remaining work. Do not commit, push, deploy, publish, send real form messages, or remove backups without authorisation.
```
