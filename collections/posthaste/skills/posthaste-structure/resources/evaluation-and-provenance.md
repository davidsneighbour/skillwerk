# Evaluation and provenance

## Research basis

Synthesised from the two user-supplied reports, "Structural Styles for Posts and Articles: A Comprehensive Taxonomy" and "Structural Systems for Posts and Articles", supplied on 21 October 2026. The first supplies the article archetypes and the distinction between containers and rhetorical structures; the second adds composable reasoning patterns, the tutorial/how-to distinction, and the problem-led TIL variation.

These resources are an editorial synthesis, not an independently verified literature review. The reports' opaque citation markers and unavailable download attachments are not usable references. The skill does not depend on those reports or their original local paths at runtime. It does not reproduce their historical attributions, platform limits, or word-count recommendations as verified facts.

The reports disagree in emphasis on TIL: one describes a sourced fact-drop, while the other describes a short personal learning note. Both forms are supported separately. The second report's stated template total differs from its enumerated list; this skill uses named layouts rather than relying on that total.

## Manual practice scenarios

Run these in a fresh conversation with the skill and only the stated material. These are evaluation prompts and expected behaviours, not claims that an independent behavioural test has passed.

| Request and material | Expected behaviour |
| --- | --- |
| "Choose a type and clean this up: I was trying to find the shortcut. Today I learned the app has a command search. Typing the action name found it. Handy when I forget a shortcut." | Choose TIL; keep one discovery, the supplied example, and the takeaway. Do not invent an app name or shortcut. |
| "Make this a successful case study: We plan to replace our onboarding email next month. We hope fewer people will ask for help." | Ask for actual implementation and results, or offer a clearly proposed problem-solution piece. Do not invent success metrics. |
| "Make this a how-to: Open Settings, select Export, choose CSV, and check that the exported file opens with the expected columns." | Use task, actions, and supplied verification. Ask only if missing environment or prerequisites materially prevent accurate instructions. Do not invent menu paths. |
| "Turn my notes into a tutorial: the new report is faster." | Ask for the learning goal, setup, exercise, and verified steps. A bare performance claim cannot support a tutorial. |
| "Use BAB for this proposed change. We spend each Friday merging reports. A shared form could collect the data once. We have not tried it." | Distinguish the observed before state from the proposed after state and bridge. Preserve that it has not been tested. |
| "Make this a research summary: a headline says coffee prevents illness." | Request the underlying study and its findings. Do not invent methods or convert association into causation. |
| "Make the supplied explainer an X thread that fits current limits." | Retain the explanation and qualifications, verify current applicable constraints, and count the full units before claiming fit. No composer or publication. |
| "Only recommend a post type for these notes." | Return the recommendation and reason without producing an unsolicited rewrite. |

For the first local trials, use the user's real drafts, assess whether type selection helps, check factual fidelity, and adjust only where observed behaviour warrants it.
